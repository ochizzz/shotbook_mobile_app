# SHOTBOOK

SHOTBOOK is a Flutter photography app built for Android first.

- **Catalog:** live photos, each with a recipe for repeating the shot on your phone (lens and zoom, ISO, shutter speed, Kelvin white balance, exposure compensation, pose, light and color).
- **PRO camera:** a manual camera that loads the recipe settings on its own.

The default language is Russian; English is available.

## Features

- **Discover**
  - A catalog of Unsplash photos with phone recipes, grouped into eight categories: portrait, street, full body, night, lifestyle, car, couple, product.
  - Search, plus a phone filter (dropdown list).
  - Photos are shown in a masonry grid; a long press opens the card menu.
  - Each card has a view counter and can be saved.
- **Photo page**
  - Recipe, pose, camera settings and editing notes, plus a guide for the phone in the recipe.
  - **Repeat shot** (main button) and **Show pose**.
  - Swipe left or right to go to the next or previous photo.
  - Share card with a QR code.
- **PRO camera** (Camera2, `ProCameraPlugin.kt`)
  - Manual ISO and shutter speed, EV, white balance from 2000 to 10000 K, manual focus.
  - iPhone-style zoom, flash, timer, RAW (DNG) where the phone supports it.
  - Filters such as B&W, applied both in the preview and in the saved JPEG.
  - Reference overlay ("repeat shot") and a one-tap reset to defaults.
  - **Apply recipe** sets everything from the photo; the ⓘ button shows camera diagnostics.
- **Accounts**
  - Email sign-up and sign-in, password recovery, profile.
  - Account deletion inside the app.
- **Safety**
  - Reports and user blocking; a photo is hidden automatically after 3 reports.
  - Privacy policy and terms of use (in `docs/`).
- **Coming later** (code is in place but switched off in `lib/shared/services/feature_flags.dart`)
  - Community feed and posting (the tab shows "coming soon").
  - Challenges.
  - The "N days in a row" badge.

## Catalog and Unsplash

- **Image hosting:** photos are loaded straight from Unsplash servers (hotlinked) and never copied to our storage, as the [Unsplash API guidelines](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines) require.
- **Attribution:** each photo shows "Photo by Author on Unsplash", with links that carry `utm_source=shotbook&utm_medium=referral`.
- **Download tracking:** saves and "repeat shot" uses are reported to Unsplash through the Supabase Edge Function `unsplash-download`. The access key lives only in the function's secret `UNSPLASH_ACCESS_KEY`; it is never in the app or in the repository.
- **Data:**
  - Recipe rows: `supabase/seed/unsplash_batch_*.json`.
  - Offline copy of the catalog: `lib/features/discover/data/seed_photo_references.dart`, generated by `tool/gen_seed.py`.
  - When online, the app loads the catalog from the `photos` table in Supabase.
- **Earlier Flickr/Openverse photos:** hidden in the database with `is_hidden = true` (migration `202611160002_unsplash_only.sql`). They have not been deleted.

### Adding a new batch

1. Collect candidates through the Unsplash API, keeping only photos with full EXIF.
2. Write the recipes, then join them with the authors and links:

   ```bash
   python3 tool/merge_unsplash.py <details.jsonl> <folder with out_*.json> <result.json>
   ```

3. Save the result as `supabase/seed/unsplash_batch_NN.json` and push it to GitHub.
4. Insert the rows into `photos`. The SQL editor can load the JSON with `extensions.http_get` from the file's raw GitHub URL.
5. Rebuild the offline copy:

   ```bash
   python3 tool/gen_seed.py supabase/seed/unsplash_batch_NN.json lib/features/discover/data/seed_photo_references.dart
   ```

## Requirements

- Flutter 3.47 stable (Dart 3.13).
- Android SDK and JDK 17.
- An Android device: the PRO camera only works on a real phone.

## Run

Without Supabase the app runs in demo mode, with the offline catalog and local saves:

```bash
flutter pub get
flutter run -d <device-id>
```

With Supabase, pass only the public client key. Never put the service key in the app.

```bash
flutter run -d <device-id> --dart-define=SUPABASE_URL=https://<project-ref>.supabase.co --dart-define=SUPABASE_ANON_KEY=<publishable-key>
```

## Supabase setup

1. Run the files in `supabase/migrations/` in filename order. They create:
   - the tables, RLS policies and Storage buckets;
   - views, reports and blocks;
   - the `delete_my_account` function;
   - the `unsplash_id` column.
2. Authentication: turn on email/password and add the redirect URL `com.shotbook.shotbook://login-callback`.
3. Edge Functions: deploy `supabase/functions/unsplash-download` with JWT verification off, and set its secret `UNSPLASH_ACCESS_KEY`.

### Release

- Release signing reads `android/key.properties` and a keystore under `android/app/`. Neither file is committed.
- Keep a backup of the keystore: without it you cannot publish updates.

```bash
flutter build appbundle --release --dart-define=SUPABASE_URL=https://<project-ref>.supabase.co --dart-define=SUPABASE_ANON_KEY=<publishable-key>
```

## Legal pages

The `docs/` folder is published by GitHub Pages from the root of the branch:

- `docs/privacy.html`: privacy policy.
- `docs/terms.html`: terms of use.
- `docs/delete-account.html`: account deletion.

Each page also has an English version (`*.en.html`). The app links to them from `lib/shared/services/legal_links.dart`.
